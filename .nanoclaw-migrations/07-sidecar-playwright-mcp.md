# 07 — Sidecar: playwright-mcp + /workspace path fix

## Intent

Expose Microsoft's `@playwright/mcp` so Chester can drive a headless Chromium browser — navigate, click, scrape, screenshot. Pairs with the simpler `agent-browser` for JS-heavy pages.

## Files (v1, in `container/playwright-mcp/`)

- `Dockerfile` — layers Caddy onto `mcr.microsoft.com/playwright/mcp:latest`; exposes 8000; runs as `node`
- `Caddyfile` — bearer-token gate on `:8000`, reverse-proxies to `127.0.0.1:8931`
- `entrypoint.sh` — validates `PLAYWRIGHT_MCP_TOKEN`; starts `node /app/cli.js --port 8931 --host 127.0.0.1 --allowed-hosts '*' --headless --browser chromium --no-sandbox` in background; waits for port 8931; execs Caddy
- `start.sh` — idempotent launcher: sources `.env`, generates `PLAYWRIGHT_MCP_TOKEN` if absent, builds image with src-hash label, `docker run -d --network nanoclaw --restart unless-stopped`

## How it's added

Same pattern as ha-mcp. `src/index.ts` calls `ensureSidecar('playwright-mcp')` (line 712 in v1).

## How agent reaches it

`mcpServers.playwright`:
```ts
playwright: {
  type: 'http',
  url: process.env.PLAYWRIGHT_MCP_URL ?? 'http://playwright-mcp:8000/mcp',
  headers: { Authorization: `Bearer ${mcpTokens.playwright}` },
}
```
Allowed tools: `mcp__playwright__*`

## Credentials

Single env var: `PLAYWRIGHT_MCP_TOKEN` (generated by start.sh, persisted to `.env`).

## Host wiring (`src/container-runner.ts`)

Same shape as ha-mcp:
- Import `PLAYWRIGHT_MCP_TOKEN`
- `-e PLAYWRIGHT_MCP_TOKEN=...`
- `--network nanoclaw`
- `playwright-mcp` in `NO_PROXY`

## **CRITICAL: /workspace path translation bug**

**The bug** (deferred from v1):

The playwright-mcp sidecar runs in its own container with its own filesystem. When Playwright saves a screenshot or download, it goes to the sidecar's local filesystem — NOT to anywhere the agent-runner container or host can read.

The agent-runner's `translateContainerPath` function in `src/path-translate.ts` only translates paths under `/workspace/group/` and `/workspace/global/` (paths bind-mounted from the host). A path like `/workspace/group/screenshot.png` would only work if the playwright-mcp sidecar ALSO had that directory mounted — but `start.sh` lines 50-62 launches the sidecar with NO volume mounts at all (no `-v` flags).

So files produced by playwright tools (screenshots, PDFs, downloads) are silently stranded in the sidecar's ephemeral container, unavailable to the agent or host IPC.

**The fix to apply during v2 migration** (since we're touching the layout anyway):

1. Create a shared scratch directory on the host: `data/playwright-scratch/` (gitignored, TTL-cleaned)
2. Mount it into BOTH containers at the same path (e.g. `/workspace/playwright-scratch/`):
   - playwright-mcp sidecar's `start.sh`: `-v "${PROJECT_ROOT}/data/playwright-scratch:/workspace/playwright-scratch"`
   - agent container (in `src/container-runner.ts`): same `-v` mount
3. Update `path-translate.ts` to translate `/workspace/playwright-scratch/` paths to the host equivalent so when the agent forwards a screenshot to a channel, the host knows where to read it from
4. Add a TTL cleanup task: cron-style sweep deleting files in `data/playwright-scratch/` older than N hours

**Or simpler alternative**: pass `--user-data-dir /workspace/group/...` to the playwright-mcp on launch so it writes inside an already-shared bind. But playwright-mcp's CLI may not support per-call output dir override.
